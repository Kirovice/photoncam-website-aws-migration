## S04 从源码生成网站文件 / ソースからのビルド

**内容与用途 / 内容・用途**：`package.json`的build脚本调用`docusaurus build`；`npm run build`执行该入口，预期生成`build/`。构建输入包含页面代码、教程、翻译、CSS、图片与网站配置。ソース・設定を静的成果物へ変換する手順を記録する。

**为什么要写 / 記載理由**：迁移构建必须明确输入、命令与输出目录；修改Markdown后，仅上传源文件不等于更新了构建后的网页。ビルド入力・実行・成果物を明確化し、編集と公開を混同しない。

源码用于编辑，build目录用于发布。Node.js运行构建工具；由此不能推导静态文件托管必须常驻Node.js。构建负责生成文件，发布负责把文件交给访问环境。

ソースは編集用、buildは公開用。ビルドでNode.jsを使用することと、静的配信でNode.jsを常駐させることは別。生成と配備を区別する。

**AWS衔接 / AWS連携**：候选流程为CodePipeline取得指定源码→调用CodeBuild执行安装与编译→收集build产物→通过后进入部署动作。CodePipeline组织整个流程，CodeBuild执行构建，并非构建完后才启动流水线。具体托管与参数在基本、详细设计确定。

CodePipelineが取得・ビルド・配備を制御し、CodeBuildが依存導入とビルドを担当する候補。具体構成・設定は設計で決める。依据 / 出典：[CodeBuild构建动作](https://docs.aws.amazon.com/codebuild/latest/userguide/how-to-create-pipeline-add.html)。

**输入与限制 / 入力・制約**：源码配置、构建调查及BUILD-ZHS.md支持构建方法；“已检查”是配置检查，不是安装、构建成功。已约定Q04在dev练习部署前确认版本并执行实际验证。設定確認と実行成功を区別し、実検証をdev演習へ引き継ぐ。

**后续用途 / 後続用途**：支持R08固定构建环境、R09使用源码产物演练；执行时保存提交、环境、日志、文件清单和页面验证结果。構築・受入で出所と結果を記録する。

## S06 构建步骤也迁入AWS / ビルドもAWSへ移行

**内容与性质 / 内容・種別**：来自用户明确要求“以后把编译的这一步也迁到AWS上”，属于已约定的项目目标。利用者の要求に基づく合意であり、実装実績ではない。

**为什么单列 / 個別記載の理由**：只在本机编译再上传到AWS，可以完成托管迁移，却仍依赖本机生成发布文件。S06突出还要迁移制作网站文件的过程，防止设计和验收漏掉这部分。S01已概括AWS构建，S06将该目标单列便于引用；编号拆分不是强制规则。

ホスティング移行に加え、生成処理もクラウドへ移す要求を明示する。S01の全体合意からこの要求を独立して参照し、実装漏れを防ぐ。

**通俗理解 / 平易な説明**：网站仍是静态网站，变化的是生成和发布的工作流程：开发者修改源码，AWS安装依赖、编译生成build，再发布。静态网站与云端构建可以同时成立。

静的サイトの生成・公開工程をAWSへ移す。サイトの配信方式とビルド実行場所は別の観点。

**后续检查 / 後続確認**：R10将约定转换为安装与构建要件，A10要求保存AWS执行与产物证据；与S01共同支持R11自动部署。验收需证明指定源码在AWS成功构建，而非只看到已上传文件。R10・A10で実行と成果物を確認し、R11の自動化へつなぐ。

**用户补充的产物原则 / 成果物原則**：同一业务源码在工具、依赖或目标配置不同的情况下，生成文件可能不同，而网站仍可能满足相同内容、显示与功能要求。AWS本身不必然导致差异。验收不要求所有生成文件与旧ZIP哈希相同；差异须可解释，内容、路径、图片、语言切换、下载和操作须按基线验证。文件哈希不同不自动说明失败，首页相似也不自动说明通过。

## S10 静态托管判断与扩展 / 静的配信判断・拡張

**内容与状态 / 内容・状態**：原先从源码和ZIP推测主要可静态托管；开发者随后说明部署内容为编译文件、无额外统计或第三方服务、App打开网站而无直接资源依赖，补强了判断。Excel已改为开发者说明与调查、状态已说明。无额外服务的答复不扩大为原服务器上所有程序均已调查。

配布物からの仮定を開発者説明で補強し、現在は説明受領済み。サーバー全処理の検証済みとは扱わない。

**通俗理解与目的 / 意味・目的**：访问者主要取得预先制作好的网页和资源。静态不等于无法交互，JS仍能提供轮播和语言切换。该判断让当前设计重点放在文件托管、URL、HTTPS、缓存和发布，不提前为未知业务建设后台或数据库。

作成済みファイルを配信する方式で、JSの操作は可能。現在の配信要求を設計入力とし、未定業務のためのサービスを先行構築しない。

**弹性原则 / 拡張方針**：维护源码、构建与发布流程，为未来新功能留下清楚的调整路径。新增页面、教程或图片通常沿用流程；登录、评论或数据保存等需求明确后，评估API、数据、架构、费用、安全与测试影响，再更新要件。弹性不保证一切功能无需改造，也不意味着现在预建所有资源。这与SC06一致。

ソース・ビルド・配備を維持し、追加要求に応じて変更経路を用意する。新しいページとバックエンド機能を区別し、具体化後に構成・費用・安全・試験を評価する。無改修の保証や未定資源の先行構築ではない。

**检查与后续 / 確認・後続**：Q10仍保留网络、路由与正式切换条件，未来按页面与操作验收；S14集中保存开发者答复与BUILD-ZHS.md来源。具体架构后续设计，完整网络与服务端配置未核验。
